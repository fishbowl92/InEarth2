## 프로토타입 시연 영상

- [InEarth2 프로토타입 시연 영상 보기](https://youtu.be/kSvXJfqgeeQ)

개발 당시 제작한 프로토타입 영상입니다. 최종 상용 버전이 아니며, 공개 저장소의 코드와 일부 차이가 있을 수 있습니다. 영상은 프로젝트의 동작을 소개하는 자료이며, 개인 기여와 공동 개발 범위는 별도 안내를 기준으로 확인해 주세요.

팀 프로젝트의 전체 코드 중 설명할 수 있는 개인 기여를 분리한 안내입니다. 아래 역할 구분은 개발자의 당시 경험 설명을 기준으로 하며, 파일 전체나 업로드 커밋의 작성자가 모든 기능의 단독 구현자라는 뜻은 아닙니다. 코드는 당시 보존 커밋에 고정된 링크로 연결합니다.

## 1. 연쇄 번개 — 공동 설계·구현 방식 논의 및 수정

### 담당한 판단

처음에는 2차원 타일에서 전파 경로를 먼저 계산하는 방식을 제안했습니다. 동료와 의사코드로 비교하면서, 성장에 따른 연쇄 횟수 증가와 이전 위치를 다시 대상으로 삼는 조건, 계산 시점과 연출 순서를 논의했습니다. 최종 코드에는 타격마다 다음 대상을 찾고 연출 사이에 실행을 나누는 코루틴 방식이 반영되어 있습니다.

이는 공동 의사결정 경험입니다. 혼자 연쇄 번개 전체를 설계·구현했다거나 성능 측정으로 개선율을 입증한 경험으로 표시하지 않습니다.

### 코드를 읽는 순서

| 순서 | 바로 볼 함수 | 확인할 내용 |
| --- | --- | --- |
| 1 | [`ChainLightning`](https://github.com/fishbowl92/InEarth2/blob/5cafabbce2eee3206fa55703ac156531e233c3f6/ScriptTable/Skill.cs#L388-L427) | 시작 대상, 피해량과 성장에 따른 연쇄 횟수 설정, 코루틴 호출 |
| 2 | [`makeChainLight`](https://github.com/fishbowl92/InEarth2/blob/5cafabbce2eee3206fa55703ac156531e233c3f6/Player.cs#L786-L812) | 다음 대상 조회 → 이펙트 이동 루프 → 피해 → 다음 탐색 기준 갱신 |
| 3 | [`returnNearEnemy`](https://github.com/fishbowl92/InEarth2/blob/5cafabbce2eee3206fa55703ac156531e233c3f6/Player.cs#L813-L837) | 인접 4방향을 임의 시작 순서로 확인하고 다음 적 하나 반환 |

현재 코드는 모든 분기 경로를 한 번에 확장하는 그래프 탐색이 아니라, 매 연쇄 단계에서 다음 대상 하나를 고르는 구조입니다. 전역 방문 기록으로 이전 위치를 금지하지 않으며 반복 횟수로 연쇄를 제한합니다.

코루틴은 별도 스레드가 아닙니다. `yield`에서 실행을 양보할 뿐, 전체 연산량을 자동으로 줄이거나 순간적인 처리 지연을 보장해 없애는 도구는 아닙니다. 이 코드에서는 타격과 연출의 순서를 표현하는 실행 구조로 확인해야 합니다.

## 2. 랜덤 맵 — 기획 단계의 생성 방식 제안

주변 타일 상태를 반복 반영하는 맵 생성 아이디어를 제안했습니다. 아래 코드는 프로젝트에 반영된 흐름을 확인하기 위한 자료이며, 맵 생성 코드 전체를 단독 작성한 것으로 주장하지 않습니다.

- [`GenerateWorld`](https://github.com/fishbowl92/InEarth2/blob/5cafabbce2eee3206fa55703ac156531e233c3f6/MapManager.cs#L1235-L1270): 격자 초기화와 생성 규칙 반복.
- [`doSimulationStep`](https://github.com/fishbowl92/InEarth2/blob/5cafabbce2eee3206fa55703ac156531e233c3f6/MapManager.cs#L1422-L1465): 인접 8칸 상태와 생성·제거 기준을 적용한 뒤 결과 반영.

## 현재 관점의 검토

- `TriggerData.ts.x/y/z`에 좌표와 피해량 등 서로 다른 의미를 재사용하여 호출 전후 해석이 달라집니다. 이름이 있는 전용 데이터 구조로 분리할 필요가 있습니다.
- 이동 루프 중 대상이 사라지는 경우, 전투 종료 시 코루틴 취소와 이펙트 반환은 추가 검증이 필요합니다.
- 이동 시간 변수와 실제 도착 판정이 같은 의미인지 확인해야 합니다.
- 과거 전체 Unity 프로젝트가 없어 이번 정리에서 실제 게임 실행이나 성능 측정은 하지 않았습니다.
